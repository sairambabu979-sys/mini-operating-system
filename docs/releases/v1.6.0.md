minios v1.6.0: files you can write, in /tmp

Everything merged after v1.5.0 (writable files, parts 1 and 2), plus
the release commit. docs/design/usermode.md describes /tmp and the new
calls, and docs/design/input.md the shell's redirections.
- /tmp: a flat directory of files held in RAM, beside the read-only
  initrd. There is no disk driver, so they are gone at reboot. At most
  32 files and 1 MiB of data in all (-ENOSPC past either); a removed
  file lives on through the fds still open on it.
- open() takes flags: O_RDONLY, O_WRONLY, O_RDWR, with O_CREAT, O_TRUNC
  and O_APPEND, Linux's numbers. Writing or making a file in the initrd
  is -EROFS.
- write() writes /tmp files; unlink() removes them.
- The shell: "a < f", "a > f" and "a >> f", alone or at the ends of a
  pipeline: "ls /bin | wc > /tmp/n", "cat < /tmp/n".
- New program: rm.
- The core of /tmp is pure code, host-tested against a model over
  20,000 random operations. The adversarial review found a write that
  faulted kept the page it had made, so a failed write took space, and
  no test read a hole; both are now caught by tests.

Changes for anyone coming from v1.5.0:
- open(path) is open(path, flags). v1.5's libsys passed 0, which is
  O_RDONLY, so v1.5 programs open to read as before; unknown flag bits
  are -EINVAL.
- New system call: unlink (14). New errnos: ENOSPC (28), EROFS (30).
- readdir("/") lists "tmp" first, then the initrd's root as before.
- An initrd may not hold a top-level tmp (mkinitrd.py refuses it).
- No change to boot_info (still version 5) or the image formats.
- The boot banner reads "minios 1.6.0".

Booted only under QEMU's TCG emulator (8.2, and 9.2 for x2APIC), with
SeaBIOS and OVMF; the host unit tests run natively. Never booted on real
hardware. README.md's known limitations list the rest.
