minios v1.3.0: arguments for programs

Everything merged after v1.2.0, plus the release commit.
- Programs take arguments. spawn(name, args) passes a NULL-terminated
  list of at most 8 strings, 256 bytes in all, and the program starts as
  main(argc, argv) with argv[0] its name. The kernel copies and checks
  every argument before it creates anything, and lays the strings and
  the vector out at the top of the new stack, 16-byte aligned.
- The shell splits each line into words at spaces (no quoting): the
  first names the program and the rest are its arguments. More than 8
  is refused with a message, as are help and exit with arguments.
- New programs: echo, which prints its arguments, and argcheck, which
  checks how they were handed over.
- Tests: arguments intact at both limits exactly, one more argument or
  byte refused, and hostile argument lists from ring 3. A review found
  four places where a planted bug passed every test; each is now caught.

Changes for anyone coming from v1.2.0:
- spawn (system call 5) takes a second argument, the argument list. NULL
  means none, which is what every v1.2.0 caller passed, so existing
  programs run unchanged. New errno: E2BIG (7), past either limit.
- A program starts with argc in RDI and argv in RSI, which crt0 hands on
  to main. main(void) still works.
- The shell no longer refuses a line with spaces: "hello world" runs
  hello with the argument "world".
- boot_info is still version 4.
- The boot banner reads "minios 1.3.0".

Booted only under QEMU's TCG emulator (8.2, and 9.2 for x2APIC), with
SeaBIOS and OVMF; the host unit tests run natively. Never booted on real
hardware. README.md's known limitations list the rest.
