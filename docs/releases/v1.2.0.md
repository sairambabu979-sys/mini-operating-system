minios v1.2.0: PS/2 keyboard, COM1 input and a shell

Everything merged after v1.1.0 (the keyboard and shell series, parts 1 to
5), plus the release commits. docs/design/input.md describes the input
path, and docs/PLAN.md section 11 records the additions and what the
reviews found.
- A PS/2 keyboard through the 8042 on IRQ 1: scan code set 1 through the
  controller's translation, US layout, every controller wait bounded, and
  the A20 and reset lines never touched.
- COM1 receive on IRQ 4. Transmit stays polled, so panic() can always
  print.
- One input queue for both, drained by read() (syscall 8): raw bytes, no
  echo. read() blocks without losing a wakeup, and rejects a bad buffer
  before it takes a byte.
- A shell (sh) that edits the line itself and runs the embedded programs
  by name, started with the new init=NAME boot option. make run-shell boots
  it with the terminal as COM1.
- Tests that type at it for real: run_tests.py drives the PS/2 keyboard
  through QMP send-key and COM1 through stdin, on the APIC and 8259 paths
  and under UEFI. In-kernel tests type through the 8042's command 0xD2 and
  the UART's loopback, so none of them needs host input.
- Fixes from adversarial reviews and the Codex review, each now caught by
  a test:
  - a key pressed during boot was read back as the 8042's configuration
    byte, leaving the boot without a keyboard;
  - COM1 bytes drained at init could be queued behind later ones;
  - reading the UART's line status while printing cleared the error bits
    of a received byte;
  - the shell held input typed ahead for the program it started.
- Release commits:
  - stage 2's A20 code now empties the 8042's output buffer before reading
    its output port, and never writes the reset bit low. A key waiting
    there would otherwise have been written back as the port and, on a
    real 8042, could reset the machine. QEMU's 8042 cannot show this, so
    no test does;
  - make run passes Ctrl-C to the guest.

Changes for anyone coming from v1.1.0:
- New system call 8, read(fd, buf, len): fd 0 only, at most 256 bytes,
  blocking for at least one. Its error order is part of the ABI:
  -EBADF, -EFAULT for the range, 0 for len 0, -EFAULT for an unwritable
  buffer, then -ENODEV with no input device.
- New boot option init=NAME (1 to 15 characters); a bad name panics.
  exit-after-init now also makes a panic exit QEMU with status 35.
- make run, make run-uefi, make run-shell and make run-shell-uefi give
  QEMU the terminal as -serial mon:stdio: Ctrl-C reaches the guest, and
  Ctrl-A x quits QEMU.
- run_tests.py starts QEMU with stdin from /dev/null, and gains
  --stdin-file, --type-after, --type and --input.
- New images: disk-shell.img, disk-uefi-shell.img and disk-badinit.img.
- boot_info is still version 4.
- The boot banner reads "minios 1.2.0".

Booted only under QEMU's TCG emulator (8.2, and 9.2 for x2APIC), with
SeaBIOS and OVMF; the host unit tests run natively. Never booted on real
hardware. The keyboard and COM1 tests that inject through 0xD2 and the
UART's loopback are QEMU-only, and would fail rather than skip on hardware
without those features. README.md's known limitations list the rest.
