minios v1.5.0: pipes

Everything merged after v1.4.1 (the pipes series, parts 1 to 3), plus
the release commit. docs/design/usermode.md describes open files and
pipes, and docs/design/input.md the shell's pipelines.
- Open files: an fd now points at a shared, counted file (the console's
  input, the console's output, an initrd file with its position, or a
  pipe end), which every fd on it shares, position included. Every fd
  closes when a process exits, however it ends.
- spawn() takes a third argument, stdio: three of the caller's fds to be
  the child's 0, 1 and 2, or NULL for the caller's own.
- pipe(): a 4 KiB buffer between a read end and a write end. A read
  waits for a byte and ends with 0 once no writer is left; a write waits
  until all of it is in, 256 bytes at a time and each piece whole, and
  gets -EPIPE once no reader is left. A bad buffer never loses a byte.
- fstat() says what an fd is: an initrd file and its size, the console,
  or a pipe and the bytes waiting in it.
- The shell runs pipelines: "cat /etc/motd | wc", up to 8 programs,
  spaces around "|" optional, reporting each one's status.
- New program: wc. cat with no arguments copies its standard input; at
  the console, input is edited a line at a time and Ctrl-D on an empty
  line ends it. cat, ls and wc report errors on fd 2, so in a pipeline
  they reach the console.
- The adversarial reviews of the three parts found an empty first line
  from cat on a serial terminal (the LF of the CRLF that ended the
  shell's line), and tests that could not see an fd left open past a
  closed one at exit, a write split in two, or an allocation failing in
  a slab. Each is now caught by a test.

Changes for anyone coming from v1.4.1:
- New system calls: fstat (12, filling a struct stat) and pipe (13).
  New errno: EPIPE (32). spawn's third argument, which v1.4's libsys
  always passed as 0, is stdio; 0 still means what it did.
- fds 0 to 2 are whatever spawn gave, not always the console; they still
  cannot be closed. read() and write() are -EBADF on a file that cannot
  do them (the console's output, an initrd file, the wrong end of a
  pipe), as they were before on those fds.
- open() can now fail with -ENOMEM.
- No change to boot_info (still version 5) or the image formats.
- The boot banner reads "minios 1.5.0".

Booted only under QEMU's TCG emulator (8.2, and 9.2 for x2APIC), with
SeaBIOS and OVMF; the host unit tests run natively. Never booted on real
hardware. README.md's known limitations list the rest.
