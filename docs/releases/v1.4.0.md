minios v1.4.0: an initrd, and files programs can read

Everything merged after v1.3.0 (the initrd series, parts 1 to 4), plus
the release commit. docs/design/boot.md describes how the initrd reaches
the kernel, and docs/design/usermode.md the file calls.
- An initrd: a ustar archive the build makes, holding every program in
  /bin, the files under rootfs/ (for now /etc/motd), and /etc/manifest,
  each file's size and FNV-1a hash. Both loaders hand it to the kernel,
  which reserves it, checks it, and keeps it for the life of the system.
- Programs load from the initrd, not from copies built into the kernel,
  which shrinks from about 690 to 430 KiB (debug build). With no usable
  initrd, the kernel panics saying it has nothing to start init from.
- Programs can read files: open, read, close and readdir, read-only, by
  absolute path, with up to 8 files open per process.
- New programs: cat and ls. The shell's help lists /bin as it is.
- The tar reader trusts nothing in the archive and is fuzzed on the
  host; the path layer is host-tested. Building part 2 turned up an
  allocator layout that would have overwritten the initrd with 4 GiB of
  RAM, and the adversarial reviews of the four parts found, among
  others, a test that let a corrupted program pass and reads that ended
  at the wrong place on a partly writable buffer. Each is now caught by
  a test.

Changes for anyone coming from v1.3.0:
- boot_info is now version 5 (initrd_phys, initrd_size), and the kernel
  refuses any other version, so both loaders and the kernel must come
  from this release.
- New system calls: open (9), close (10) and readdir (11, filling a
  struct dirent); read (8) also reads a file's fd. New errnos: ENOTDIR
  (20), EISDIR (21), EMFILE (24). fds 3 to 10 are files; 0 to 2 are
  still the console.
- Paths are absolute: "/" is the root, a trailing "/" names a directory,
  and an empty, "." or ".." component is -EINVAL. There is no current
  directory.
- Every image carries the initrd: mkimage and mkesp take --initrd, and
  tools/gen_user_images.py is gone. New images: disk-noinitrd.img and
  disk-badinitrd.img, which must panic.
- The boot banner reads "minios 1.4.0".

Booted only under QEMU's TCG emulator (8.2, and 9.2 for x2APIC), with
SeaBIOS and OVMF; the host unit tests run natively. Never booted on real
hardware. README.md's known limitations list the rest.
