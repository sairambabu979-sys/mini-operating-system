minios v1.4.1: hardening, and builds on an Apple Silicon Mac

Everything merged after v1.4.0, plus the release commit. The fixes were
first written on a separate local branch (local-wip), then ported one
at a time onto main, each with tests and an adversarial review. Nothing
programs see has changed.
- COM1: the startup self-test waits for its looped byte (a bounded
  wait) and always leaves loopback; a UART that failed it used to stay
  in loopback and swallow everything sent. The receive drain counts
  dropped (errored) bytes against its limit, so a receiver reporting bad
  bytes as fast as they are read cannot hold the CPU in IRQ 4.
- Output to COM1 still waits for the transmitter, however long. A bound
  was tried and measured: QEMU ran through 2,000,000 polls in under 3
  seconds of its host side pausing (Ctrl-S, a slow terminal), and output
  was lost. docs/design/console.md has the detail.
- An xAPIC IPI still pending after a million pauses panics, naming it,
  instead of hanging.
- Memory: a vmm_map() that fails part-way leaves nothing of the range
  mapped, and a range that wraps, leaves the canonical addresses or
  crosses into the other half is refused. A failed vmalloc() or iomap()
  gives its address range back instead of abandoning it, without
  shortening the quarantine that catches use of freed kernel stacks.
- macOS on Apple Silicon: the host tests build (string.c's loops for a
  non-x86 host, tested on x86 too), the UEFI firmware Homebrew's QEMU
  ships is found, and README.md says how to build and test with
  Homebrew. Not yet run on a Mac.
- Tests: a model 16550 UART in the host tests, and kernel tests that
  make the page allocator fail on cue (pmm_test_fail_after).

Changes for anyone coming from v1.4.0:
- No system call, boot_info (still version 5) or image format changed.
- vmm_map() now guarantees a failure maps nothing, and refuses ranges it
  used to map partly.
- run_tests.py's OVMF_CODE is used alone when set, and a missing file is
  an error rather than a silent fallback; OVMF_VARS needs OVMF_CODE.
  make run-uefi and run-shell-uefi find the firmware the same way.
- The boot banner reads "minios 1.4.1".

Booted only under QEMU's TCG emulator (8.2, and 9.2 for x2APIC), with
SeaBIOS and OVMF; the host unit tests run natively. Never booted on real
hardware. README.md's known limitations list the rest.
