# CPU tables, exceptions and panics

Sources: `kernel/arch/x86_64/{gdt,idt,traps,extable}.c`, `isr.asm`,
`setjmp.asm`, `kernel/core/{panic,ksyms,ubsan,stack_protector}.c`.

## GDT and TSS

| Selector | Descriptor | Why it is here |
|----------|------------|----------------|
| `0x00` | null | required |
| `0x08` | kernel code, 64-bit | `SYSCALL` loads `CS = STAR[47:32]` |
| `0x10` | kernel data | `SYSCALL` loads `SS = CS + 8` |
| `0x18` | user code, 32-bit | placeholder: `SYSRET` computes user selectors from this base |
| `0x20` | user data | `SYSRET` loads `SS = base + 8` |
| `0x28` | user code, 64-bit | `SYSRET` loads `CS = base + 16` |
| `0x30` | TSS (16 bytes) | ring-0 stack for user→kernel entries, IST stacks |

IST stacks: `#DF` (IST1), NMI (IST2), `#MC` (IST3), 16 KiB each. These
exceptions can arrive when the current stack is unusable, and a handler
that runs on a broken stack escalates straight to a triple fault.

## Entry path

256 stubs, generated by a NASM macro, normalize the stack so every vector
produces the same `struct trap_frame`:

```
stub:        [push 0 if the CPU pushes no error code] push vector; jmp isr_common
isr_common:  push 15 GPRs; swapgs if CS.RPL == 3; cld; call trap_dispatch(rsp)
             restore; swapgs if returning to ring 3; drop vector/error; iretq
```

The CPU aligns RSP to 16 before pushing its frame, and the 22-qword frame
keeps it aligned at the `call` (enforced by a `static_assert`). Every
offset the assembly uses comes from `asm-offsets.inc`.

## Dispatch policy

| Situation | Response |
|-----------|----------|
| A test armed `trap_expect()` for this vector | record vector, error code, CR2 and handler RSP; resume via fixup or `klongjmp` |
| `#BP` | log, count, continue (the saved RIP already points past `int3`) |
| NMI | log, continue |
| Kernel fault at an exception-table address | resume at the fixup |
| Anything else from kernel mode | `panic_trap()` |
| User mode | (M7) kill the process; until then, panic |

The **exception table** (`__ex_table`, emitted with `EXTABLE_ENTRY()`) is
how code declares that one instruction may fault on purpose. M7 builds
`copy_from_user` on it. The M2 tests use it to provoke and survive every
exception class.

## Panic

`panic()` assumes nothing about the system: polled serial only, no locks,
no allocation, interrupts off, and a recursion guard. A panic prints:

```
exception 14 (#PF page fault), error code 0x2, from kernel mode
page fault: write hit a non-present page in kernel mode
RIP/RSP/RFLAGS, all GPRs, CR0 CR2 CR3 CR4 EFER
backtrace:
  #0  0xffffffff80101ad9 selftest_page_fault+0x9
  #1  0xffffffff801019b3 kmain+0x403
  #2  0xffffffff80100035 _start+0x35
```

The backtrace follows the frame-pointer chain (`-fno-omit-frame-pointer`,
with `RBP = 0` set in `_start`). Each frame is checked for alignment,
location in the kernel window, and upward progress before it is followed,
so a corrupt chain ends the walk instead of faulting inside the panic.
Return addresses are looked up at `ret - 1`, so a call at the very end of
a function is attributed correctly.

**Symbols** come from a two-pass link. Pass 1 links with an empty table,
`tools/gen_ksyms.py` extracts the text symbols, and pass 2 links the real
table into `.rodata`, which sits after `.text`, so no function can move.
The build then re-extracts symbols from the final binary and fails if
anything moved.

## Sanitizers in the kernel

- **UBSan** (debug builds): `-fsanitize=undefined`, with a freestanding
  runtime in `core/ubsan.c`. Undefined behaviour panics with file:line. Tests
  can arm `ubsan_expect()` to observe one report instead.
- **Stack protector**: `-fstack-protector-strong
  -mstack-protector-guard=global`. `_start` seeds the canary from the TSC,
  and its low byte is always zero, so string overflows cannot forge it.

The OOB test caught a real bug in its own first version: the write went
past a stack array, UBSan reported it, and the stack protector then caught
the smashed canary. Both nets fired, in the expected order.

## Tests

`tests/kernel/test_traps.c` provokes `#UD`, `#DE`, `#BP`, `#GP`
(non-canonical access) and `#PF` (read and write, checking CR2 and the
error code). It also forces a genuine **double fault** by pointing RSP at
unmapped memory and executing `int3`: `#BP` → `#PF` → `#PF` → `#DF`. The
test then verifies that the handler ran on the IST1 stack.
`tests/kernel/test_ubsan.c` covers overflow, out-of-bounds and shift
reports. The `disk-panic.img` QEMU run checks the full panic output
against expected patterns.
